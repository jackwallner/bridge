# Localized metadata from keyword research, 2026-11-20

Ten locales rewritten: tr, nl-NL, th, da, de-DE, fr-FR, el, zh-Hant, it, en-GB. Nothing was uploaded to App Store Connect. Evidence is a snapshot from Apple search hints (autocomplete, per storefront) and the iTunes Search API (top 25), taken 2026-11-20. Ranks are for the metadata live before this change, so they are the baseline. Our listing often did not appear at all in the API for local queries even where the old name and subtitle contained the words (de, fr, nl, it, gr); treat "not in top 25" as a weak signal, and the API as unreliable for brand-new apps with 0 to 1 ratings.

Indexing, from Apple's table ([App Store localizations](https://developer.apple.com/help/app-store-connect/reference/app-information/app-store-localizations)): every storefront below indexes en-GB as its secondary locale (en-US is not indexed there). So en-GB name, subtitle and keywords reach TR, NL, TH, DK, DE, FR, GR, IT, TW and HK as well as GB. en-GB was therefore given its own English set (it no longer copies en-US) and the local locales avoid spending bytes on English words. fr-FR and zh-Hant are also indexed by the US storefront.

Competitor subtitles could not be read: apps.apple.com no longer serves the subtitle (it shows the category). Competitor titles and rating counts below come from the search API.

Common finding: demand in these storefronts is thin and mostly "bridge" + a verb (play, learn, practise). Autocomplete returned bridge-specific terms only in a few storefronts; elsewhere "bridge" suggestions were construction games, "Bridge Constructor", Bridge Race and score keepers. The bridge-card meaning is clear only when the local card noun or verb is added, so each name/subtitle pairs "bridge" with a local card or bidding word.

## Keyword fill (2026-11-21)

Scope: `keywords.txt` only, 35 locales that used under 90 of the 100 characters. Every field is now 95 to 100 characters (Python `len()`). Nothing else was edited and nothing was sent to App Store Connect.

Indexing, from Apple's table (fetched 2026-11-21): every storefront in this list indexes en-GB as its secondary locale except the US, which indexes ar-SA, zh-Hans, zh-Hant, fr-FR, ko, pt-BR, ru, es-MX and vi. India indexes en-GB plus bn-BD, gu-IN, hi, kn-IN, ml-IN, mr-IN, or-IN, pa-IN, ta-IN, te-IN and ur-PK; Pakistan indexes ur-PK. No per-storefront download table was supplied with the task, so that weighting rests on the US-indexing fact and on the 2026-08-27 audit (US 936 of 3,069 impressions). en-US already carries `contract, tutor, beginner, lesson, drill, defense, declarer, quiz, play, trump, hand, duplicate, offline`; added terms are local words, not repeats of those.

Evidence (all snapshots 2026-11-21): Apple search hints per storefront, plus the iTunes search API top 25 for a few queries. The demand that did show up is generic card-game vocabulary: "offline" / "without internet" (ar, ru, uk, id, pt, ja), "gratis / free" (es, fr, ja, pt), "online", and the local noun for card game. Bridge terms (contract, trump, quiz and so on) are standard local vocabulary, not autocomplete-backed. Competitor brand names were not used. One in-field repeat I left: any keyword that is an inflected form of a name or subtitle word (hr `licitacija`, ru `торговля`, sk `hra`) stays, because the check is exact-token and Apple's stemming per language is unknown.

Competitor shape (titles only, since apps.apple.com no longer serves subtitles): Fun Bridge, Bridge Base Online, Bridge by NeuralPlay and PVBridge sit first in every storefront; local-language bridge apps exist only in zh-Hans (`桥牌学堂` family, `桥牌做庄练习`, `桥牌双明手题`), ja (`コントラクトブリッジ`) and ru/uk (`Contract Club`).
