## Notes

- SM-3 residual window, below the bar. RevenueCat counts a cache as fresh for 25 hours while the app is backgrounded (`DeviceCache.swift:216-225`, `:996-997`). If the player leaves the app within the second or two before `confirmMembership()` runs, while the first refresh is still in flight, a cached "not a member" up to 25 hours old could confirm. Reaching harm also needs a renewal made outside the app within those hours, and a reminder still on despite that cache. In practice the launch that cached the lapsed record would already have confirmed and turned the reminder off. A one-line hardening would close it: require `Date().timeIntervalSince(info.requestDate) <= Self.freshBaselineAge` before confirming. The constant already exists for this purpose.
- SM-3 during a RevenueCat server outage: the SDK may compute a record offline from StoreKit (`CustomerInfoManager.swift:533`). That record is not cached and reflects Apple's current entitlements, so a non-member read there is StoreKit's answer. A promotional entitlement granted only in RevenueCat would read as "not a member" in that window. This is noted for completeness. The app is not known to use promotional grants.
- SM-3 confirms once per process. An unconfirmed launch (offline, or a failed sync) waits for the next cold launch. That is conservative: the reminder stays.
- SM-2 choice cards: Undo after Next now re-shows the answered card, and Next sends it to the back again. Undo on a choice card is therefore mostly a "look again". It matches the review's defensible record, but it is a visible change in what Undo does there. Jack may want to know.
- SM-4: ledger days saved before the upgrade have no scope, so in the first week after the update the old fake gain can still appear once. The effect ends within 7 days, and nothing is dropped.
- SM-1: launch fires both `onAppear` and the `.active` hook, so a notDetermined toggle sends two `requestAuthorization` calls. iOS shows one alert. Harmless as far as the code shows.
- In run 42370421160, `testLapsedMembersStaleRecordTurnsTheReminderOffWithoutAnIsProChange` took 81.7 s (2.7 s in the revert run). It passed. This looks like first-touch cost in the test host, not a hang in the code under test, but it is worth watching if the suite starts timing out.
- `project.yml` pins RevenueCat `from: 5.72.0`, so builds take the newest 5.x. SM-3 depends on the SDK's fetch-policy semantics, which were the same at 5.80.3 and 5.102.3. Re-read them on SDK bumps.
- No widget or watch targets exist. No new user-facing strings were added. No layout code changed.
