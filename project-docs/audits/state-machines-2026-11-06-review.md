### Missed by the audit

Nothing new beyond the audit's scope. Within it, SM-3's premise and real population were missed: the audit marked "whether RevenueCat reports an expired cached record as inactive" unconfirmed and ranked it third as "small", when the pinned SDK source answers it and the affected group is the normal lapse path. The weekday badge on the locked Home tile (HomeView.swift:591) is a further symptom of the same state.

## What survived, ranked

1. SM-3: weekly Game Night reminder never cancelled for members who lapse while away more than 3 days. Most lapsed reminder users, weekly, indefinitely, unswitchable in the app.
2. SM-1: reminder toggle can show on with nothing scheduled. Proven route is rare; would move up if a device test shows restore or a permission cycle drops pending requests.
3. SM-2: Undo leaves the undone answer in accuracy stats. Frequent, near-zero cost.
4. SM-4: membership change inside a week fakes a weekly gain. Rare, small cost.

## Method changes that would have prevented the errors

- Read the pinned third-party source before calling a premise unconfirmed. Package.resolved pins RevenueCat 5.80.3 and the source is public; `isDateActive` settles SM-3 in minutes. Test fixtures should go through the real decode path, not a public test init that sets the computed answer (`EntitlementInfo(isActive:)`), which only restates the assumption.
- For each bug, test the counterfactual: what does the state look like if the player skips the triggering action? That catches SM-2's overstated cost, since the requeue gives the same record.
- Do not state platform behaviour as fact. "iOS drops pending requests when permission is revoked" was asserted and then used to rank SM-1 first; mark it unverified and rank only on routes the code proves.
- Read the code between a delay and its side effect before claiming a window (P7).
- Pin the audited commit with `git rev-parse HEAD` and re-check file:line citations against it at write time (38f9417 does not exist; SettingsView lines were 30 off).
- Separate "the test asserts a documented promise" from "the test asserts the design I prefer", and say which in the evidence column (SM-2).

## Appendix: review checks (run 42299097245, removed after the run)

`StateMachineReviewChecks` in BridgeTests, using a `RevenueCatClient` fake like PaywallFunnelTests'.

- `testStaleCachedRecordOfALapsedMemberNeverMakesIsProTrue`: builds the server JSON (`request_date` 5 days ago; `Bridge+` entitlement and monthly subscription `expires_date` 1 day ago), decodes it with `JSONDecoder` (`.convertFromSnakeCase`, `.iso8601`, as RevenueCat's own decoder), asserts `isActive == false`, sets it as `cachedCustomerInfo` with the same record as the fresh fetch, calls `start()`, and asserts the collected `$isPro` values never contain true.

- `testMemberRowEarlierInTheWindowIsTheBaseline`: the audit's SM-4 setup plus a member-scope ledger row 6 days ago; asserts `weeklyGain` is nil.
